# Printer setup and compatibility

## Profiles

Each configured printer has a stable internal ID, display name, tagged `connection`, 58/80 paper mm, actual raster width (128–832, divisible by 8), copies (1–3), cutter enable, local font family and size (12–48 px). Font size is the base size of the receipt body in dots; the invoice header and total rows scale it by fixed percentages, so one setting rescales the whole design (see [ESC/POS and Persian rendering](escpos.md#printed-design)). Default UI uses 80mm/576 dots; changing paper size does **not** silently overwrite actual dot width. Choose 384 for common 58mm mechanisms only if the manual agrees. Saved job profiles are immutable snapshots.

Spooler connection (`{type: "spooler", queueName}`): prints RAW ESC/POS bytes through a print queue already installed on the operating system — Windows spooler (`winspool`) or CUPS (`lp -d <queue> -o raw`) on Linux/macOS. **This is the recommended way to use USB receipt printers**: the vendor driver the customer installed stays in place and no libusb/libusbK driver replacement is ever required (replacing the USB driver breaks other POS software using the same printer). `printers.installed` (UI: «پرینترهای نصب‌شده», SDK: `getInstalledPrinters()`) lists the queues so the operator only picks a name. Internally the connection stays tagged as `spooler`; for older frontend compatibility, `printers.list`/`printer.get` can expose the reserved USB-shaped `vendorId: 0`, `serial: "queue:<name>"` descriptor. Use SDK `spoolerQueueName(connection)` before taking a USB branch, and never request WebUSB for the queue marker. For a spooler profile `online` means the queue exists and the spooler answers — not that the device is powered — and `completed` means the OS spooler accepted the document; the spooler may hold it if the printer is off. Direct-USB profiles remain available for driverless setups.

USB descriptor: VID/PID, optional serial, bus and port topology, interface, alternate setting, bulk OUT endpoint. Manufacturer/product are discovery metadata. With serial: match VID/PID/serial; multiple matches rejected. Without serial: physical topology is used, never bus address (which changes on reconnect). Changing hub/port or bus topology can require re-selection; identical serial-less printers cannot be magically distinguished. Access-denied discovery can list descriptors but not serial/product. Re-select after permission setup if needed.

Only standard class 0x07 printer interfaces are selectable through discovery. Never treat HID/storage/vendor interfaces as generic printers. All saved endpoint data is revalidated against live descriptors before sending. USB permission errors are actionable, not retried forever. Vendor-specific support requires a device contract and hardware tests. Direct USB is optional at compile time (`--features libusb`) and excluded from default builds; saved USB profiles report a clear disabled-feature error when opened by a build without that feature.

A USB profile may have one operator-configured local `usbFallbackTarget` (spooler queue or network connection); it is empty by default and cannot be changed remotely. It is used only if the USB failure is known to occur before the first job byte (`PreOpen` or `PostOpenPreWrite`) and no earlier copy was sent. A partial/failed write, timeout, unknown state, or failure after a copy forbids fallback. The selected route is pinned for all copies in the job. Details and stage matrix: [USB failover policy](usb-failover.md).

LAN: exact RFC1918 IPv4, default 9100, adjustable port through local UI, no DNS/public IP/loopback/link-local. Use DHCP reservation/static address to avoid silent address changes. Probe makes a connection only; it does not send dummy ESC/POS. Wrong service at that address may accept connections, so operator must confirm with actual print. Configure invoice, kitchen, bar routes in Settings; PWA reads routes in `agent.status`. The Windows 7 Legacy agent offers the same direct LAN (TCP/9100, private IPv4) per printer, alongside installed Windows RAW spooler queues. The modern agent can also auto-discover LAN printers on the local subnet via `discover.network` (web app: `printerAgent.discoverNetwork()`), so the operator no longer needs cmd/PowerShell/terminal to find IPs. A discovered printer can then be saved straight from the web app via `printer.save` (SDK `savePrinter()`), so full setup needs no cmd/PowerShell/terminal or the local settings window.

## Status meaning

`online`: USB device identity present / TCP connection succeeds. Not paper/cutter/cover/temperature confirmation. `offline`: absent/unreachable. `unknown`: not probed or enumeration failed. `busy`: current hardware transfer, visible in printer list; job `printing` events also indicate activity. `error`: representable in protocol; actual job has structured errors. USB changes are checked at most once every ten seconds, not OS hotplug notification; no claim of instantaneous unplug detection. Probing skips the active printer when observed, but is advisory and cannot reserve hardware.

## ESC/POS variants

GS v 0 raster support is assumed; some printers need a different image command, pacing or driver. Printer-specific code pages are not used for Persian. Rasterization increases byte volume and print time. QR/barcode/cash drawer commands differ by model/firmware and are not exposed to the remote v1 document schema. Never enable a cash drawer command without matching voltage/pin/timing documentation.

No real model is certified by this change. Track manufacturer, model, firmware, USB driver/interface, dot width, raster/cut behavior and OS/browser in the hardware acceptance sheet. `printer.test` prints the configured profile in millimeters and raster dots, plus a centered heading, sample column row and pixel rule; rendering uses the profile's configured `widthDots`. ESC/POS and generic spooler APIs cannot reliably detect the physical roll width, so compare the printed profile and margins with the printer manual—this is a profile check, not hardware sensing. Update the profile if needed and test again. `completed` means bytes were handed off, not proof of paper output; **inspect the paper** to validate encoding, alignment, clipping and cutter. If physical output fails despite successful writes, require model-specific status commands and a human decision; do not auto-replay.
