# پرامپت ایجنت — توسعهٔ فرانت MenuVex: پرینترهای نامحدود با نام‌های سفارشی، SYNC با دستیار، و نام‌گذاری در QZ Tray

> این پرامپت را به ایجنتِ فرانت (ایجنتِ پروژهٔ سایت/اپ سفارش‌گیری منویکس — همان «فرانت») بده.
> ایجنت به کل پروژه دسترسی دارد و می‌داند چه چیز به چه چیز وصل است؛ این پرامپت «چه» را می‌گوید و «چطور» را خودش از کد悟 می‌کند.

---

## ۱. هدف (Goal)

صاحب کافه/رستوران در **دستیار MenuVex** (اپ دسکتاپی — ریپوی `menuvex-printer`) پرینترهای خودش را تعریف می‌کند و به هر کدام یک **نام/ایستگاه دلخواه** می‌دهد:

- پرینتر x → **صندوق**
- پرینتر y → **آشپزخانه**
- پرینتر z → **هرچی که خودش تعریف می‌کند** (چون کافه‌ها و رستوران‌ها با هم فرق دارند)

**هیچ محدودیتی در تعداد پرینترها نباید باشد** — هر چندتا پرینتر داشت، تعریف می‌کند.

حالا می‌خواهیم:

1. **SYNC**: پرینترهایی که در دستیار تعریف شده‌اند، **در فرانت (سایت) هم باشند** — یعنی وقتی کاربر در سایت می‌خواهد چاپ کند، فهرست کامل پرینترهای دستیار (با همان نام‌های سفارشی) را ببیند و بتواند به هر کدام چاپ کند.
2. **فرانت بدون محدودیت ۳ پرینتر** — هر جایی از فرانت که کاربر «فقط ۳ پرینتر» می‌تواند انتخاب کند (مثلاً فهرست ثابت صندوق/آشپزخانه/بار یا یک selector با ۳ خانه) را حذف کن.
3. **QZ Tray را خراب نکن** — چون **۲ روش و ۲ سیستم متفاوت** داریم (agent SDK و QZ Tray). تغییرات باید افزوده (additive) باشند.
4. **در QZ Tray هم** کاربر باید بتواند خودش تعریف کند **کدام پرینتر برای چیست** (نام/برچسب هر پرینتر QZ — مثلاً صندوق، آشپزخانه).

## ۲. وضعیت فعلی — آنچه در ریپوی دستیار انجام شده (PR #13)

این قسمت **قبلاً انجام شده** (روی برنچ `arena/bb9441a7-menuvex-printer`، PR #13) — فقط verify کن:

- **Backend (Rust)**: دیگر هیچ محدودیتی روی تعداد پرینتر / route / raw-settings نیست (`Config::validate` در `src-tauri/src/config/mod.rs`).
- **نام ایستگاه (route role) free-text شد** — نام‌های فارسی مثل «صندوق» قبول می‌شوند (قبلاً فقط ASCII بود). ID پرینترها هنوز strict است.
- **نام پرینتر (Printer.name)** از قبل free-text بود (حداکثر ۱۲۸ بایت، بدون کاراکتر کنترلی) — نام فارسی برای پرینتر کاملاً کار می‌کند.
- **SDK** (`sdk/src/types.ts`): `routeSchema.role` حالا free-text است (`text(128).min(1)`); `printerId` strict. `printerSchema` و `statusSchema` (که `routes` را هم دارد) بدون هیچ تغییری (backward compatible).
- **PWA دستیار** (`src/components/Settings.tsx`): بخش «مسیرهای چاپ» دیگر ۳ نقش ثابت (invoice/kitchen/bar) ندارد — ایستگاه‌ها داینامیک‌اند: افزودن/ویرایش نام/حذف، انتخاب پرینتر، تیک «چاپ خودکار»، و chips «صندوق/آشپزخانه/بار» برای افزودن سریع. محدودیت تعداد ندارد.
- **تست‌ها**: `npm test` (42 passed)، `npm run build`، و `cargo test` در CI سبز است.

پس **سمت agent آماده است** — تو فقط باید 프론트 را با آن sync کنی.

## ۳. کاری که تو در فرانت باید انجام بدهی (Your task)

### ۳.۱. SYNC پرینترهای دستیار با فرانت

- منبع حقیقت (source of truth) **دستیار (agent دسکتاپ)** است، نه فرانت. فرانت نباید فهرست پرینتر خودش را hard-code کند.
- فرانت از طریق **SDK** (`sdk/` در ریپوی دستیار — `PrinterAgentClient`) با agent محلی (WebSocket روی `127.0.0.1` + secret) وصل می‌شود:
  - `client.getPrinters()` → فهرست کامل پرینترها با `name` (نام سفارشی/ایستگاه)، `id`، `status` — **همه را نشان بده، نه ۳ تا**.
  - `client.getStatus()` → `routes` (نام ایستگاه → `printerId` + `autoPrint`) — برای «چاپ خودکار به ایستگاه X».
  - `client.print({ printerId, jobId, document })` — چاپ به پرینتر انتخاب‌شده (`printerId` همان IDی است که agent می‌شناسد).
- UI انتخاب پرینتر در فرانت: فهرست کامل، **جستجو/فیلتر با نام سفارشی** (فارسی/عربی/لاتین)، بدون هیچ محدودیت — هر چندتا پرینتر که در دستیار تعریف شده، همان‌جا باشد.
- اگر agent در دسترس نیست (down / not paired) — **QZ Tray باید همچنان کار کند** (سیستم دوم).

### ۳.۲. حذف محدودیت «۳ پرینتر» در فرانت

- هر محدودیت یا فهرست ثابتی که کاربر را به ۳ پرینتر محدود می‌کند (۳ ایستگاه ثابت صندوق/آشپزخانه/بار، یا selector با ۳ خانه) را **remove** کن.
- ایستگاه‌ها/roleها را داینامیک کن: هر نام سفارشی، هر تعداد.
- **Backward compatibility**: configهای قدیمی agent که routeهای `invoice`/`kitchen`/`bar` دارند، باید همچنان کار کنند — فقط نباید limited به آن ۳ تا باشی.
- **نمایش نام‌های قدیمی**: routeهایی که کلید legacy دارند (`invoice`/`kitchen`/`bar`) را در UI فرانت با همان برچسب‌های فارسیِ قبلی نمایش بده (`invoice`→صندوق، `kitchen`→آشپزخانه، `bar`→بار)، نه با کلید انگلیسی — کاربرانی که اپ را آپدیت کرده‌اند، باید ایستگاه‌های خودشان را با همان نام‌های آشنای قبلی ببینند.

### ۳.۳. QZ Tray — خط قرمز: خرابش نکن

- **۲ روش چاپ وجود دارد**: (۱) agent SDK (دستیار MenuVex)، (۲) **QZ Tray** (از طریق مرورگر به اپ QZ Tray). هر دو باید **کامل و دست‌نخورده** باقی بمانند.
- تغییرات تو در QZ Tray باید **additive** باشد: هیچ flow موجود QZ (connect → انتخاب پرینتر → print) را نشکن.
- **علاوه بر این**: در تنظیمات QZ Tray یک **printer labeling** اضافه کن — کاربر برای هر پرینتر QZ یک نام/برچسب تعریف می‌کند (مثلاً «صندوق»، «آشپزخانه») و در انتخابگر پرینتر QZ همان نام‌ها نمایش داده می‌شوند. این نگاشت **محلیِ فرانت** است (agent از پرینترهای QZ خبر ندارد).

### ۳.۴. نکات UI

- UI فارسی (RTL) — نام‌های فارسی پرینتر/ایستگاه باید درست نمایش داده شوند.
- اگر پرینتر جدیدی در دستیار تعریف شد و فرانت باز است — refresh خودکار (event/poll) خوب است؛ حداقل با refresh دستی.

## ۴. قوانین و محدودیت‌ها (Constraints — خط قرمز)

1. **QZ Tray را نشکن** — ۲ سیستم متفاوت‌اند؛ تست دستی هر دو روش چاپ (agent + QZ Tray) الزامی است.
2. **هیچ محدودیتی در تعداد پرینتر** — نه در agent (انجام شد)، نه در فرانت.
3. **نام‌ها free text** — فارسی، عربی، لاتین، هر什么.
4. **امنیت agent را تغییر نده**: raw ESC/POS فقط با opt-in محلی (global + per-printer) — وب‌سایت نمی‌تواند روشنش کند؛ USB fallback فقط به مقصد صریحِ تنظیم‌شده و فقط بعد از صفر بایت ارسال‌شده؛ spooler شبکه/CUPS دست‌نخورده.
5. **Backward compatibility**: configهای قدیمی با routeهای `invoice`/`kitchen`/`bar` باید کار کنند.
6. **پروتکل Agent ↔ Front را تغییر نده** (schemaهای SDK در ریپوی دستیار همین‌اند) — اگر تغییر لازم شد، PR جداگانه بزن.
