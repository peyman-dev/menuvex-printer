# چاپ USB روی همهٔ نسخه‌ها (ویندوز ۷، ویندوز، لینوکس، مک)

هدف: پرینتر حرارتی USB روی همهٔ سیستم‌ها کار کند — **بدون WebUSB، بدون تعویض درایور به WinUSB، و بدون نیاز به IP/شبکه.**

## تصمیم معماری (مهم)

روی **ویندوز** دو راه بدون WinUSB وجود دارد:

- **USB مستقیم با درایور داخلی خود ویندوز (Agent قدیمی / Legacy):** ویندوز ۷ برای هر پرینتر USB استاندارد (کلاس Printer) خودش «USB Printing Support» را نصب می‌کند. Legacy همین دستگاه را **خودکار پیدا می‌کند** و مستقیم به آن چاپ می‌کند؛ نه درایور کارخانه‌ای لازم است، نه ساختن صف ویندوز، نه CMD/PowerShell.
- **«اسپولر RAW ویندوز»:** درایور USB خود پرینتر را در ویندوز نصب می‌کنید و Agent بایت‌های ESC/POS را از طریق همان صف ویندوز می‌فرستد.

هر دو راه به WinUSB یا تعویض درایور نیاز ندارند (ابزار کارخانه‌ای و سایر نرم‌افزارهای صندوق سالم می‌مانند).

روی **لینوکس و مک**، USB مستقیم با libusb انجام می‌شود (روی لینوکس با مجوز udev).

Agent قدیمی (Legacy) روی «ویندوز ۷ SP1 و جدیدتر» اجرا می‌شود؛ پس روی ویندوز modern هم می‌توانید همان مسیر بدون‑WinUSB را داشته باشید.

| سیستم        | مکانیزم USB                                  | کجا                                |
| ------------ | -------------------------------------------- | ---------------------------------- |
| ویندوز ۷     | USB مستقیم با درایور داخلی ویندوز (پیدا شدن خودکار) یا اسپولر RAW | Agent قدیمی (Legacy)               |
| ویندوز 10/11 | اسپولر RAW بدون WinUSB؛ USB مستقیم فقط در build با feature `libusb` | Agent قدیمی (Legacy) یا Agent مدرن |
| لینوکس       | اسپولر/CUPS به‌صورت پیش‌فرض؛ USB مستقیم در build با `libusb` + مجوز udev | Agent مدرن |
| مک           | اسپولر/CUPS به‌صورت پیش‌فرض؛ USB مستقیم در build با `libusb` + دسترسی USB/Keychain | Agent مدرن |

## ویندوز ۷ (Agent قدیمی / Legacy)

1. کابل USB پرینتر را وصل و پرینتر را روشن کنید. نصب درایور لازم نیست.
2. Agent قدیمی را باز کنید → «افزودن پرینتر». جستجو خودکار انجام می‌شود و پرینتر با برچسب سبز **USB** در فهرست می‌آید (اگر بعداً وصلش کنید، فهرست خودش به‌روز می‌شود و کنار ساعت هم خبر می‌دهد).
3. پرینتر را انتخاب کنید → «افزودن پرینتر انتخاب‌شده» → نام (مثلاً «صندوق»)، عرض کاغذ و کاربرد → «ذخیره و چاپ آزمایشی».

IP وارد نمی‌کنید و صف ویندوز نمی‌سازید. اگر پرینتر در فهرست USB نیست، کابل را جدا و دوباره وصل کنید؛ برخی مدل‌های خاص به‌جای کلاس استاندارد Printer، «پورت COM مجازی» یا کلاس اختصاصی سازنده دارند و باید با درایور خودشان نصب و از نوع اتصال «صف چاپ ویندوز» استفاده شوند. پرینتری که درایورش از قبل نصب است هم با برچسب **ویندوز** در همان فهرست دیده می‌شود.

## ویندوز 10/11

دو گزینه:

- **Agent قدیمی (Legacy) روی ویندوز modern:** برای همان مسیر بدون‑WinUSB، Legacy را نصب و دقیقاً مثل ویندوز ۷ از «USB مستقیم» یا «صف چاپ ویندوز» استفاده کنید. این ساده‌ترین و کم‌ریسک‌ترین راه است.
- **Agent مدرن + USB مستقیم:** این مسیر فقط در build با Cargo feature `libusb` موجود است و اگر مدل/درایور WinUSB سازگار باشد کار می‌کند. درایور به‌صورت خودکار عوض نمی‌شود. اگر درایور سازگار نیست، از صف نصب‌شده یا LAN استفاده کنید؛ تعویض درایور می‌تواند ابزار کارخانه‌ای یا سایر نرم‌افزارها را خراب کند.

## لینوکس

USB مستقیم فقط در build دارای feature `libusb` فعال است. یک‌بار مجوز udev را طبق [`linux.md`](linux.md) تنظیم کنید (اسکریپت کمکی)، بعد در Agent مدرن «جستجوی USB» → انتخاب دستگاه → «چاپ آزمایشی».

## مک

USB مستقیم فقط در build دارای feature `libusb` فعال است. Agent را از DMG به Applications منتقل کنید؛ دسترسی USB/Keychain را تأیید کنید → «جستجوی USB» → انتخاب → «چاپ آزمایشی». جزئیات در [`macos.md`](macos.md).

## پیدا کردن IP پرینترهای LAN (بدون cmd/PowerShell)

اگر پرینترها با کابل لن به روتر وصل هستند، لازم نیست با `cmd`/`arp`، PowerShell یا پنل روتر دنبال IP بگردید. Agent مدرن subnet محلی را روی پورت ۹۱۰۰ اسکن می‌کند و فهرست کاندیدها را به اپلیکیشن می‌دهد:

- وب‌اپ: `printerAgent.discoverNetwork()` را صدا بزنید → `[{ host, port }]` (تا ۴ پرینتر یا بیشتر، هر کدام یک پروفایل).
- افزودن مستقیم از وب‌اپ: برای هر کاندید، `printerAgent.savePrinter({ id, name, connection: { type: "network", host, port }, paperMm, widthDots, copies, cut, fontFamily: "Noto Sans Arabic", fontSize })` — نیازی به رفتن به تنظیمات Agent نیست.
- هر کاندید را با «چاپ آزمایشی» تأیید کنید؛ «قابل اتصال» یعنی «چاپ شد» نیست.
- Agent قدیمی (Legacy) هم همین اسکن را در صفحهٔ «افزودن پرینتر» خودکار انجام می‌دهد — روی **همهٔ کارت‌های شبکهٔ** کامپیوتر و بدون نیاز به اینترنت — و IPهای صف‌های TCP/IP ویندوز را هم بررسی می‌کند. پرینتر پیدا‌شده با یک کلیک اضافه می‌شود.

## شرط درایور (ویندوز)

درایور باید ESC/POS را **بدون تغییر** به پرینتر بگذراند. درایورهای «XPS» یا «host‑based‑only» معمولاً بایت‌های RAW را دستکاری می‌کنند و نامناسب‌اند. اگر خروجی به‌هم‌ریخته بود، به یک درایور Generic/Text یا درایور سازگار با ESC/POS سوییچ کنید و دوباره «چاپ آزمایشی» بزنید.

«ارسال شد» یعنی بایت‌ها به ترانسپورت تحویل شد (برای اسپولر: به ویندوز؛ برای USB مستقیم: به درایور USB ویندوز؛ برای LAN: پذیرش TCP)، نه تأیید چاپ روی کاغذ. کاغذ را بررسی کنید؛ نتیجهٔ نامشخص را قبل از چاپ مجدد بازبینی کنید.

## WebUSB چرا در این راه نیست

WebUSB یک API مرورگر است و روی مرورگرهای قدیمی ویندوز ۷ کار نمی‌کند. Agent بومی این محدودیت را دور می‌زند و **نیازی به تغییر کد WebUSB سایت نیست**؛ SDK می‌تواند تابع WebUSB موجود را بدون تغییر به‌عنوان fallback تزریق کند (جزئیات در [`connection-compatibility-fa.md`](connection-compatibility-fa.md) و [`integration.md`](integration.md)).

## وضعیت و گام بعدی

- USB از طریق صف نصب‌شده روی همهٔ سیستم‌ها پشتیبانی می‌شود؛ libusb مستقیم فقط در build اختیاری با feature `libusb` فعال است. مسیر fallback امن USB قبل از اولین بایت و فقط به مقصدی که اپراتور انتخاب کرده اجرا می‌شود؛ timeout یا ارسال ناقص هرگز fallback نمی‌شود. جزئیات در [`usb-failover.md`](usb-failover.md).
- Agent مدرن از صف چاپ نصب‌شدهٔ سیستم‌عامل در همهٔ پلتفرم‌ها پشتیبانی می‌کند؛ بنابراین برای حفظ درایور پرینتر، روی ویندوز هم می‌توان از صف RAW موجود استفاده کرد. build و چاپ واقعی هر پلتفرم همچنان باید در CI و سخت‌افزار تأیید شود.
